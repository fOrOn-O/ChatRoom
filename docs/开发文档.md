# ChatRoom 开发文档

> 版本：v1.1
>
> 更新日期：2026-07-23
>
> 文档定位：当前实现说明与架构指南

ChatRoom 是一个面向小型团队与社区场景的即时通讯项目。系统采用前后端分离架构：Go 服务端负责认证、业务接口、消息持久化与 WebSocket 连接管理；Vue 3 前端提供联系人、群组、实时消息和文件传输工作台。

本文档只描述仓库中已经存在的代码与可运行流程。产品演进方向统一放在文末路线图，避免将方案与现状混淆。

### 2.1 请求路径

普通 HTTP 请求经过以下链路：

~~~
浏览器
  → Gin 路由
  → CORS / 日志 / Recovery
  → JWT 鉴权（受保护接口）
  → Handler 参数校验与业务处理
  → GORM / MySQL
  → 统一 JSON 响应
~~~

实时消息走独立的 WebSocket 链路：

~~~
浏览器 WebSocket
  → JWT 鉴权
  → Upgrade
  → Client.ReadPump
  → Hub 私聊或群聊 Channel
  → MySQL 消息持久化
  → 目标 Client.Send
  → Client.WritePump
~~~

### 2.2 组件职责

| 组件 | 职责 |
| --- | --- |
| Gin Router | 路由分组、公共中间件与鉴权边界 |
| Handler | 请求绑定、权限判断、数据库读写与响应组装 |
| Hub | 维护在线用户和群组成员映射，串行处理注册、注销和消息路由 |
| Client | 对应一个 WebSocket 连接，负责读泵、写泵与心跳 |
| GORM Model | 描述关系型数据模型与表映射 |
| Pinia Store | 管理登录态、联系人、群组、会话消息与未读数 |

## 4. 服务生命周期与并发模型

### 4.1 服务启动

服务入口位于 backend/cmd/server/main.go，启动顺序如下：

1. 读取配置并初始化日志。
2. 建立 MySQL 与 Redis 客户端。
3. 创建 Hub，并在独立 Goroutine 中运行 Hub 事件循环。
4. 创建 Gin 路由并启动 HTTP Server。
5. 监听 SIGINT 与 SIGTERM，通过带超时的 Shutdown 完成优雅关闭。

### 4.2 Client 读写分离

每个 WebSocket Client 启动两个 Goroutine：

| Goroutine | 责任 |
| --- | --- |
| ReadPump | 接收浏览器帧、解析事件、路由 chat、read_receipt 与 typing |
| WritePump | 从 Send Channel 取消息、JSON 序列化、写入 WebSocket、定时 Ping |

这样可以保证单个慢连接不会阻塞其他连接的消息分发。Client 的发送缓冲区大小为 256；Hub 对慢消费者采用非阻塞投递策略，避免主循环被阻塞。

### 4.3 Hub 事件循环

Hub 持有以下 Channel：

| Channel | 作用 |
| --- | --- |
| register | 注册新的在线连接 |
| unregister | 清理断开的连接 |
| private | 路由单聊消息 |
| group | 路由群聊消息 |
| broadcast | 广播系统消息 |

Hub 的 Run 方法使用 select 串行消费这些事件。在线用户与群组成员索引使用 RWMutex 保护：写操作在注册、注销阶段进行，消息投递使用读锁读取当前连接。

### 4.4 重复登录与连接状态

同一用户建立新连接时，Hub 以最新连接覆盖在线映射；用户断开时仅清理仍然指向该 Client 的映射，避免旧连接影响新会话。上线与下线状态以 online_status 事件通知其他在线用户。

## 5. 数据模型

数据库初始化脚本位于 backend/scripts/init.sql。核心实体如下：

| 表 | 用途 | 关键字段或索引 |
| --- | --- | --- |
| users | 用户身份与资料 | username 唯一索引、email 唯一索引、status |
| friends | 双向联系人关系 | user_id 与 friend_id 唯一组合 |
| groups | 群组元数据 | owner_id、name、status |
| group_members | 群成员与角色 | group_id 与 user_id 唯一组合、role |
| messages | 聊天消息 | msg_id 唯一、发送者、接收目标、创建时间 |
| read_receipts | 最后已读位置 | user_id、target_id、target_type 唯一组合 |
| files | 上传文件元数据 | md5、uploader_id、文件路径 |

消息接收目标使用两种类型：

- user：一对一会话，to_id 为对方用户 ID。
- group：群组会话，to_id 为群组 ID。

群成员角色约定：

| role | 含义 |
| --- | --- |
| 0 | 普通成员 |
| 1 | 管理员 |
| 2 | 群主 |

## 6. HTTP API

### 6.1 通用约定

- 基础前缀：/api/v1
- 响应格式：code、message、data
- 受保护接口：Authorization: Bearer token
- 文件上传：multipart/form-data，字段名为 file
- 分页参数：page 与 page_size

成功响应示例：

~~~json
{
  "code": 0,
  "message": "success",
  "data": {}
}
~~~

### 6.2 健康检查与认证

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | /health | 否 | 服务健康检查 |
| POST | /api/v1/auth/register | 否 | 注册用户并返回 JWT |
| POST | /api/v1/auth/login | 否 | 校验密码并返回 JWT |

注册请求：

~~~json
{
  "username": "alice",
  "password": "example-password",
  "nickname": "Alice"
}
~~~

### 6.3 用户与联系人

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/v1/user/profile | 获取当前用户资料 |
| PUT | /api/v1/user/profile | 更新昵称、头像、签名、邮箱、手机号 |
| GET | /api/v1/users/search?keyword= | 搜索用户名或昵称 |
| GET | /api/v1/friends | 获取联系人列表 |
| POST | /api/v1/friends/request | 创建双向联系人关系 |
| DELETE | /api/v1/friends/:friend_id | 删除双向联系人关系 |

添加联系人请求：

~~~json
{
  "user_id": 2,
  "remark": "产品同学"
}
~~~

### 6.4 群组

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/v1/groups | 获取当前用户所在的群组 |
| POST | /api/v1/groups | 创建群组并加入创建者与受邀成员 |
| GET | /api/v1/groups/:group_id | 获取群组资料 |
| GET | /api/v1/groups/:group_id/members | 获取群成员 |
| POST | /api/v1/groups/:group_id/members | 邀请成员 |
| DELETE | /api/v1/groups/:group_id/members/:user_id | 移除成员 |
| POST | /api/v1/groups/:group_id/leave | 退出群组 |

创建群组请求：

~~~json
{
  "name": "产品讨论",
  "description": "产品与交付协作",
  "member_ids": [2, 3]
}
~~~

### 6.5 消息与文件

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/v1/messages | 按目标、类型和分页查询历史消息 |
| POST | /api/v1/messages/read | 记录最后已读消息 |
| POST | /api/v1/messages/:msg_id/revoke | 撤回当前用户发送的消息 |
| POST | /api/v1/files/upload | 上传图片或文件 |
| GET | /api/v1/files/:file_id/download | 鉴权下载文件 |

历史消息查询示例：

~~~
GET /api/v1/messages?target_id=2&target_type=user&page=1&page_size=50
~~~

已读请求示例：

~~~json
{
  "target_id": 2,
  "target_type": "user",
  "last_msg_id": "59ffb838-6a50-4d9c-94e7-12cdd75269a1"
}
~~~

## 7. WebSocket 协议

### 7.1 建立连接

连接地址：

~~~
ws://localhost:8080/ws?token=token
~~~

浏览器 WebSocket 受限于无法自由添加 Authorization Header，因此服务端同时支持 Authorization Header 与 token 查询参数。前端在 HTTPS 页面会自动使用 WSS。

### 7.2 客户端事件

#### chat

~~~json
{
  "type": "chat",
  "data": {
    "msg_id": "59ffb838-6a50-4d9c-94e7-12cdd75269a1",
    "to_id": 2,
    "to_type": "user",
    "content_type": "text",
    "content": "你好，今天的评审准备好了吗？"
  }
}
~~~

content_type 支持 text、image、file；to_type 支持 user、group。

#### typing

~~~json
{
  "type": "typing",
  "data": {
    "target_id": 2,
    "target_type": "user"
  }
}
~~~

#### read_receipt

~~~json
{
  "type": "read_receipt",
  "data": {
    "target_id": 2,
    "target_type": "user",
    "last_msg_id": "59ffb838-6a50-4d9c-94e7-12cdd75269a1"
  }
}
~~~

前端同时通过 HTTP 已读接口持久化最后已读位置。

### 7.3 服务端事件

| type | 说明 |
| --- | --- |
| chat | 新的单聊或群聊消息 |
| chat_ack | 服务端确认消息已进入路由流程 |
| online_status | 用户上线或下线状态 |
| typing | 对方正在输入提示 |

chat_ack 示例：

~~~json
{
  "type": "chat_ack",
  "data": {
    "msg_id": "59ffb838-6a50-4d9c-94e7-12cdd75269a1",
    "status": "sent"
  }
}
~~~

## 8. 前端工作台

前端使用 Vue 3、Pinia、Vue Router、Axios 与 Element Plus，入口位于 frontend/src。

### 8.1 页面与状态

| 模块 | 责任 |
| --- | --- |
| Login / Register | 表单校验、注册登录、保存 token |
| User Store | 登录态、个人资料获取与退出 |
| Chat Store | 联系人、群组、当前会话、消息缓存、未读数、在线状态 |
| Chat View | 会话列表、历史消息、实时消息、群组详情、上传和资料编辑 |
| WebSocket Module | 建连、重连、事件订阅、发送聊天/输入/已读事件 |

### 8.2 前端代理与部署变量

开发服务器将以下路径代理到后端：

| 路径 | 用途 |
| --- | --- |
| /api | REST API |
| /ws | WebSocket |
| /static | 上传文件静态资源 |

部署时可使用以下前端变量：

| 变量 | 示例 | 用途 |
| --- | --- | --- |
| VITE_API_BASE_URL | https://example.com/api/v1 | API 地址 |
| VITE_WS_URL | wss://example.com/ws | WebSocket 地址 |

## 9. 本地开发与验证

### 9.1 前置条件

- Go：以 backend/go.mod 声明的版本为准
- Node.js 20+
- MySQL 8+
- Redis 7+

### 9.2 启动后端

~~~powershell
cd backend
Copy-Item configs/config.example.yaml configs/config.yaml
~~~

填写本地配置后初始化数据库并启动服务：

~~~powershell
Get-Content scripts/init.sql | mysql -u root -p
go mod download
go run ./cmd/server
~~~

后端默认地址为 http://localhost:8080。

### 9.3 启动前端

~~~powershell
cd frontend
npm install
npm run dev
~~~

前端默认地址为 http://localhost:5173。

### 9.4 校验命令

~~~powershell
# 后端
cd backend
go test ./...

# 前端
cd frontend
npm run build
~~~

## 10. 部署建议与演进路线

### 10.1 生产部署建议

- 使用 HTTPS 与 WSS，并由反向代理统一处理证书、静态资源与长连接升级。
- 使用独立的生产数据库、Redis 实例与高强度 JWT 密钥。
- 将配置保留在部署环境中，仓库只维护 config.example.yaml。
- 为服务端添加运行指标、错误告警和访问日志归集。

### 10.2 演进路线

1. 完善消息同步体验：离线消息拉取、更细粒度的已读状态与会话排序。
2. 提升多人协作体验：更丰富的群组角色和通知策略。
3. 面向规模化部署：多实例 WebSocket 协同、消息分发与对象存储。
4. 提升工程质量：接口测试、并发测试、性能基线与持续集成。
